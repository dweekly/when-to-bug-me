## Unreleased

Reload, Back and polling never ask again or log twice. A new view, `#/review` (linked from Home and the Record), sketches the weekly review from this browser's record: estimated time by project against Jordan's stated priorities (synthetic, and kept out of every prompt), settled or asked, feedback taps, and Dispatch reports against their estimates (Copy and each report now enter the record; a missing cost shows "not reported"; the public demo's report is labeled synthetic).
- **Stage 10a: onboarding for Jordan.** `#/welcome` (linked from Home and Rules): Bug Me reads 30 of Jordan's past decisions (a new synthetic fixture), drafts a "how to work with me" note in which every line cites the decisions behind it, interviews Jordan about what it saw (voice or typing; DEMO REPLY bound to each question), and revises the note, showing what changed and which answer changed it. Code checks every citation and limit. Recorded, with a tour ("Getting to know you"). Jordan's persona no longer claims its note came from an onboarding interview; it was written by hand.

- **Stage 9: the runner.** `npm run runner` runs Bug Me on your own Mac, owner-only, on loopback (reachable from a phone with `tailscale serve`). It drafts and routes with your Claude Code login (`claude -p --safe-mode --no-session-persistence`, prompt on stdin), so briefs and asks never pass through Cloudflare. Launch starts a brief as a background Claude Code session in its own worktree (`claude --bg --worktree`), once however often it's pressed, from the stored brief only, after every "You first" item is ticked, in a trusted repo where the needed tools are connected; the brief then shows how the session is doing. "How?" gives short numbered steps for each "You first" item (recorded for the demo's briefs), and on the runner "Do it with me" opens a Claude in Chrome guide in Terminal. The owner page picks up new asks without a reload. Copy command now also passes `--allowedTools mcp__bugme`. The local route's text no longer promises a local model.

- **Stage 8: Dispatch.** A rough task, said or typed, becomes a brief before a session starts: stage, estimate, a stopping point at twice it where the session asks instead of growing the job, out of scope, model, effort and permission mode, tools turned off, prerequisites and check-ins. The model drafts inside enums from a catalog of tools and skills; code checks the quotes, decides where it runs (sensitive and not urgent: run locally, recommended only), keeps Bug Me's own server on, and turns needed tools that aren't connected into prerequisites. Copy command (off until every prerequisite is ticked) gives one fully quoted `claude` line whose opening prompt carries the brief and the person's own words. On `/me`, briefs live in the owner's queue and are never cached or recorded; `mcp/bugme.mjs sync-catalog` sends tool names and statuses; sessions link asks to their brief and report with the new `report_to_bug_me`. The public site has three recorded demo tasks and a Dispatch demo. Also: two private project names removed from a unit test (they remain in history; David's call).
- **DEMO REPLY on live servers too.** Staging and production run live Claude, where DEMO REPLY was hidden (as "Use Jordan's words" had been). Jordan's scripted words replay the recording at no cost, so it now shows everywhere but the owner's page. The demos' step text says "press DEMO REPLY".
- **Stage 6f: the card in Jordan's words.** Each option is labelled the way Jordan would say it ("Keep using the old tax table", not "Keep T-19 mapping"), from the fast model, with the agent's own labels under More context; the decision button and Bug Me's read-backs use the same words, and the pros and cons are unchanged. The agent's pick is no longer on the card: after the decision Bug Me reveals what the agent would have picked and what it guessed, and if Jordan went against either without a reason, asks ("What made you go against the agent?"), even if the conversation asked once. One 🤔 Huh? button sits just above the box. DEMO REPLY, beside the microphone, replaces "Use Jordan's words (recorded)". On a phone Bug Me's words use the full width, the source label sits underneath, and there is one firefly, which scrolls away with the header. The header drops "Synthetic · recorded Claude"; Tours are Demos. Titles prompt 2026-10-13.2, conversation prompt 2026-10-13.2; eval 10/10.
- **Stage 6e: "Huh?"** A 🤔 Huh? button under the card's question, then on Bug Me's latest turn: one press and Bug Me says it again in plain English (what's going on, what each option would do, any term defined, the question again), up to 700 characters, from the agent's material only. Typing "I don't follow" does the same. Presses don't count toward Bug Me's two questions or the thread's six turns; two per thread. A Huh? on the read-back leaves the decision button lit, and a yes after the explanation still answers the read-back. Each miss is logged with the answer as `unclear: n`, feedback on Bug Me's translation rather than on the decision, so it never becomes guidance about the person. The Lost in translation tour presses it. Prompt 2026-10-13.1; eval 10 cases (one rewritten after its first run, see docs/STAGE-6E.md).
- **Stage 6c: the decision as a conversation, on the page.** Below the card, the person and Bug Me take turns: words or a click go to `/api/converse`, Bug Me's reply appears with the firefly, and the person's turns are marked with what it heard. Once Bug Me reads the decision back, the primary button is the decision itself; pressing it sends it down the usual path (a typed "yes" lights the same button): pushback, the revealed guess and guidance, which continue in the thread. Other courses and rejected questions are recorded as such and can still become guidance; open questions go to the agent; nothing decided opens Skip. "I'm curious: why?" stays quiet when the conversation already asked. The thread is kept with the answer and re-opens read-only; a decision being talked through is not re-routed under the person. The as-you-type parse and per-question asks are gone from the page. Tours talk through each decision with Jordan's scripted turns. Saved mornings from earlier versions start fresh.
- **Stage 7: live fire.** Real Claude Code sessions can ask Bug Me through a small MCP server (`mcp/bugme.mjs`, tools `ask_bug_me` and `check_bug_me`). Bug Me routes each ask against the owner's rules (starting from eleven distilled from David's CLAUDE.md), settles only what a permission-granting rule covers within $1, and queues the rest on a private page, `/me`: the same app, signed in with a one-time link. The owner's answer, reason and guidance go back to the asking session. A per-owner Durable Object holds the queue; nothing from it reaches the repo, logs, cache or recordings. Off unless `LIVE_TOKEN` is set.
- **Stage 6d: Decided for you, redesigned.** One sentence says what the jobs are, once. They are grouped by kind of work (merged branches, patch updates, formatting and lint, flaky tests), each group closed until opened, with one short line per job: what was done, in the past tense (from the fast model's titles), and the project. Every job has the same three icon actions, Undo, Ask! and Disagree, quiet until hovered or focused and always labeled on phones. A group's rule shows only when asked. No route glyphs, rule codes or per-row Why.

Each decision gets an emoji, a short title and past-tense "done" lines from Claude Haiku 5.5, recorded for 39 of 40. The tours' conversations are scripted and recorded.
