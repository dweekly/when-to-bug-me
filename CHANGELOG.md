# Changelog

## Unreleased

- **Usability pass on the decision card.** Found by driving the app end to end rather than by reading it.
  - **The reason box no longer cuts you off.** It was capped at 600 characters, which `maxlength` enforced silently: a long explanation simply stopped accepting keystrokes mid-sentence, exactly when someone was giving the rich context the product exists to collect. The cap is now 1500, and a counter appears in the last 200 characters so it is never a surprise. Six turns of that still leave the conversation prompt inside the bound `tests/unit/converse.test.ts` asserts.
  - **Line height in the box was 2.0** (19px text on 38px lines), which read as loose and unfinished. Now 1.6, matching the conversation turns, which already carry the same underline marks.
  - **The box keeps its full width.** DEMO REPLY and the microphone sit in a 40px strip along the bottom, instead of reserving 150px on the right of *every* line to clear two buttons in one corner — which also meant the last line ran under them as the box grew. Two now-redundant rules removed.
  - **Bug Me's read-back is its own line,** with a quiet amber rule beside it, instead of inline bold that switched weight mid-sentence and read as stray emphasis.
  - **The focus indicator is visible.** `--line` on the page background is 1.42:1, under the 3:1 that WCAG 1.4.11 requires for a focus indicator, so a keyboard user could not see which box they were in. It is now the glow, at 13.4:1.
- **The box you answer in is the one lit surface on the page.** It is paper white with dark navy ink, on a night canvas where nothing else is — so there is no reading to do to find where your answer goes. Its microphone is a filled glow button and DEMO REPLY is quiet beside it. The same treatment carries to Dispatch's "What do you want done?" and to the answer bubbles in the onboarding interview, which were the same control wearing three looks.
  - **The card's box takes the caret when the card opens,** so a decision can be answered by typing or talking without reaching for it first. Only on the card's first draw, never scrolling (the question is above the box and has to stay in view), and not on touch, where focus would open the keyboard over the decision.
  - **Every box you write in is paper, everywhere:** the reason box, the guidance Bug Me proposes, a rule being edited, the set-aside reason. One rule to learn — paper means this one is yours to fill — instead of a different look per screen. A box that isn't yours to fill yet (the set-aside reason, before a reason is picked) is an empty dashed outline rather than paper at half opacity, which was a grey slab that pulled the eye to the one thing that couldn't be used.
  - **One microphone, one look.** It is a lit button everywhere, since speaking is the way in the product is built around; it was a grey outline in some places and the lit thing in others. Listening adds a halo to the pulse, so the two states still never read alike.
  - **The set-aside question is asked once.** Its label and its placeholder were the same sentence; the label stays, because it is still there once there are words in the box.
  - **The "Me" in the wordmark carries the firefly's own light.** That is a new exception to the one-light rule, so the rule's comment names it.
  - **The focus ring moved outside the box.** The glow is 13.4:1 on the night page but 1.5:1 on paper, so an indicator drawn on the box's own border would have failed WCAG 1.4.11 the moment the box turned white. It is a 2px ring on the page instead.

- **A second usability pass: it should be obvious what to read, and where to answer.**
  - **The question leads the card.** It used to come fourth, under the briefing, the rule quote and the More context disclosure — three blocks of chrome before the one sentence that has to be read. The question is now the first thing under the breadcrumb, and the briefing and the rule that makes it yours support it from underneath.
  - **The reason box looks like a box.** It was a transparent textarea with no border and a hairline somewhere below it, so the placeholder read as a caption rather than the primary input on the card. It now has its own surface, a border, room for three lines before it grows, and the microphone and DEMO REPLY inside it. Focus lights the whole border in the firefly's colour instead of a 2px underline.
  - **The microphone is the lit thing in that box,** and DEMO REPLY (demo scaffolding) the quietest. Speech is the way in the product is built around; it was the greyer of the two.
  - **What went down to the agent is folded away.** On the closing screen it was seven lines of dense monospace — the longest text there and the least of what anyone has to read — competing with "Next decision". It is now one line that opens on a press.
  - **The payload's reach line is labelled** ("Who reads it: …"), the same words the figure's own text alternative already used. It was a bare sentence floating under the options.
  - **Dead CSS removed:** `.think-marks` and a comment describing a marks-behind-the-textarea layer that nothing has rendered for some time. The marks are drawn on the conversation turns, which is what the comment now says.

- **One type scale.** The stylesheet had grown to 18 distinct font sizes, including six pairs a half-pixel apart (16/16.5, 15/15.5, 14/14.5, 13/13.5, 12/12.5, 11/11.5) that read as inconsistency rather than hierarchy, and three weights. It is now eight sizes — 40, 20, 19, 16, 15, 14, 13, 12 — and two weights, documented at the top of `public/style.css` so it does not drift again. Emphasis comes from weight, colour or italic, never from a size that sits beside an existing one.

- **Stage 11: answering the submission review.**
  - **Pushback:** Bug Me no longer argues with a reason already given. The rule is quoted back only when the person picked with no reason, so the flight decision is one prompt shorter.
  - **Measured time:** each stretch a decision's card is on screen, while the tab is visible, is logged to the record as `{kind: "attention"}`. `#/review` shows it next to the estimate.
  - **README:** the settle invariant now separates what code checks from what the asking agent declares, and says what an MVP would enforce on its own. See `docs/STAGE-11.md`.

- **Stage 10b: onboarding on your own history (runner only).** `npm run onboard` turns rows extracted from your transcripts into onboarding's history: answered questions only, newest 200, allowed projects only (an allow list you pass; a private deny file can exclude more). It sends them to the runner, which drafts the note with your Claude login; the interview and revision run on `/me#/welcome`. **Keep it** makes the lines facts (by id, so keeping twice adds nothing; never rules) and your "how to work with me" note, which every owner model call then uses. Facts are editable in Rules on `/me`. The hosted Worker refuses owner onboarding; every call is uncached and unrecorded.

- **Stage 10d: hooks into Bug Me (mirror only).** Best-effort mirroring of Claude Code questions and plan approvals on configured machines. A hook script, `mcp/bugme-hook.mjs` (dependency-free, a 2-second deadline, silent, always exits 0), posts AskUserQuestion and ExitPlanMode to a new `/api/me/mirror`, which stores the question and answers at once; routing and titling run afterwards from the owner's Durable Object alarm. Each question gets one ticket per session, tool call and question, so repeats and a lost PreToolUse don't matter, and an answer that lands before routing finishes stands. On `/me` a mirror shows under "In your sessions", briefed, with what Bug Me would have done and "Answer it in the session"; it has no decide button, and the server refuses to settle, resolve or send anything down for it. PostToolUse records the answer by session (picked, typed, or several picks); Stop, SessionEnd or 18 hours with nothing closes it. The open page updates and closes mirrors without a reload. Plan approvals carry no plan text.

- **Stage 10c: reflection prompts.** Finishing a project with Next counts a change of project, and decides there, once, what that screen offers: after about 10 estimated minutes of answers since the last suggestion (each answer counted by its route: ● 3 min, ◐ 1 min; nothing is timed), one dismissible line suggests a break ("~13 min of real decisions est. · Stand up before Billing?"); on the first change of project and at most every third after, "Were those N worth your time?" takes one of three taps (● all worth it, ◐ some should have been settled, ○ none needed me), logged to the record as `{kind: "feedback"}` with the decisions it covered, and exported with it. Reload, Back and polling never ask again or log twice. A new view, `#/review` (linked from Home and the Record), sketches the weekly review from this browser's record: estimated time by project against Jordan's stated priorities (synthetic, and kept out of every prompt), settled or asked, feedback taps, and Dispatch reports against their estimates (Copy and each report now enter the record; a missing cost shows "not reported"; the public demo's report is labeled synthetic).
- **Stage 10a: onboarding for Jordan.** `#/welcome` (linked from Home and Rules): Bug Me reads 30 of Jordan's past decisions (a new synthetic fixture), drafts a "how to work with me" note in which every line cites the decisions behind it, interviews Jordan about what it saw (voice or typing; DEMO REPLY bound to each question), and revises the note, showing what changed and which answer changed it. Code checks every citation and limit. Recorded, with a tour ("Getting to know you"). Jordan's persona no longer claims its note came from an onboarding interview; it was written by hand.

- **Stage 9: the runner.** `npm run runner` runs Bug Me on your own Mac, owner-only, on loopback (reachable from a phone with `tailscale serve`). It drafts and routes with your Claude Code login (`claude -p --safe-mode --no-session-persistence`, prompt on stdin), so briefs and asks never pass through Cloudflare. Launch starts a brief as a background Claude Code session in its own worktree (`claude --bg --worktree`), once however often it's pressed, from the stored brief only, after every "You first" item is ticked, in a trusted repo where the needed tools are connected; the brief then shows how the session is doing. "How?" gives short numbered steps for each "You first" item (recorded for the demo's briefs), and on the runner "Do it with me" opens a Claude in Chrome guide in Terminal. The owner page picks up new asks without a reload. Copy command now also passes `--allowedTools mcp__bugme`. The local route's text no longer promises a local model.

- **Stage 8: Dispatch.** A rough task, said or typed, becomes a brief before a session starts: stage, estimate, a stopping point at twice it where the session asks instead of growing the job, out of scope, model, effort and permission mode, tools turned off, prerequisites and check-ins. The model drafts inside enums from a catalog of tools and skills; code checks the quotes, decides where it runs (sensitive and not urgent: run locally, recommended only), keeps Bug Me's own server on, and turns needed tools that aren't connected into prerequisites. Copy command (off until every prerequisite is ticked) gives one fully quoted `claude` line whose opening prompt carries the brief and the person's own words. On `/me`, briefs live in the owner's queue and are never cached or recorded; `mcp/bugme.mjs sync-catalog` sends tool names and statuses; sessions link asks to their brief and report with the new `report_to_bug_me`. The public site has three recorded demo tasks and a Dispatch demo. Also: two private project names removed from a unit test (they remain in history; David's call).
- **DEMO REPLY on live servers too.** Staging and production run live Claude, where DEMO REPLY was hidden (as "Use Jordan's words" had been). Jordan's scripted words replay the recording at no cost, so it now shows everywhere but the owner's page. The demos' step text says "press DEMO REPLY".

- **Stage 6e: "Huh?"** A 🤔 Huh? button under the card's question, then on Bug Me's latest turn: one press and Bug Me says it again in plain English (what's going on, what each option would do, any term defined, the question again), up to 700 characters, from the agent's material only.
